# LeadFlow Workspace: Complete User and Maintenance Guide

LeadFlow is a browser-based workspace for running a focused client service from first prospect research through delivery and follow-up. It is designed for a single operator who needs a clear working path, separate client files, reusable messaging, delivery checklists, and portable backups.

> **Important:** LeadFlow saves your work in the browser you are using. Create regular backups before clearing browser data, changing computers, or using a private/incognito browser window. A backup is your portable copy of the client collection.

## 1. What Each Part of LeadFlow Does

The left-side **Client Path** is the normal working sequence. You do not need to use every section in one sitting; move forward as the client relationship develops.

| Stage | Use it for | You should leave with |
|---|---|---|
| Today’s briefing | Choosing the most important next action | One clear task to do now |
| Prospects | Recording businesses and useful observations | A short, personalized outreach list |
| The $350 offer | Reviewing the fixed-price starter offer | A clear offer summary to copy or send |
| Scope builder | Filling in the client, lead source, and tool | A client-specific scope of work |
| Client onboarding | Gathering operating details after the scope is accepted | The details needed to start confidently |
| Kickoff desk | Running the 45-minute kickoff call | Decisions, owners, access, and dates |
| Seven-day delivery | Tracking the work from setup through handoff | A visible delivery status |
| Messages & testing | Copying message templates and recording safe tests | Approved messages and verified workflow steps |
| Handoff & follow-up | Closing the work and asking for the next conversation | A clean closeout and next-step plan |

## 2. Your First 10 Minutes

When you open LeadFlow, start on **Today’s briefing**. The large action strip tells you the recommended next move. The first client file is a safe starter file; rename it before you begin real work so the workspace stays organized.

1. Select **Client files** in the upper-right corner.
2. Enter the client’s business name. This is the name that appears in the client file.
3. Add a project name if helpful. Project names are optional, but they are useful if one client has more than one engagement. Examples include “Lead Follow-Up Tune-Up,” “Spring Intake Reset,” or “Website Inquiry Workflow.”
4. Save the name changes. The client file will show the project name when one is available; otherwise it will show the client name.
5. Select **Prospects** and add your first real business observation, or go directly to **Scope builder** if the client has already agreed to speak with you.

## 3. Create and Manage Client Files

Every client has an independent workspace. That means its prospects, scope fields, delivery progress, kickoff checklist, tests, and completion status stay attached to that one client file.

| Task | Steps |
|---|---|
| Create a client file | Select **Client files**, enter a client name, optionally enter a project name, then create the workspace. |
| Switch files | Open **Client files**, select the client you want to work on, and LeadFlow returns you to that file’s briefing. |
| Rename a file | Open **Client files**, edit the client name or optional project name, and save. |
| Remove a file | Open **Client files**, select the removal option for that file, and confirm the action. LeadFlow keeps at least one file so the workspace always remains usable. |
| Check progress | Open **Client files** to see the saved progress for each client, then open the correct file before making updates. |

### A Simple Naming System

Use the **client name** for the business and the **project name** for the engagement. For example:

| Client name | Optional project name |
|---|---|
| Cedar & Stone Plumbing | Lead Follow-Up Tune-Up |
| Juniper Dental | New Patient Inquiry Flow |
| Harborview Electric | Quote Request Follow-Up |

This makes it easier to recognize the right workspace when you have several active clients.

## 4. Run the Daily Client Workflow

LeadFlow works best when you take one focused action at a time. Avoid trying to write outreach, build a scope, configure delivery, and finish follow-up in one session.

### Step 1: Add a Prospect

Open **Prospects** and select the option to add a prospect. Enter the business name and one observation that is useful and truthful. A good observation is specific, public, and connected to the offer.

> Good: “The quote form has no visible response-time expectation.”  
> Avoid: “Your lead process is broken.”

Use the message action for that prospect when you are ready to personalize an email or direct message.

### Step 2: Use the Fixed-Price Offer

Open **The $350 offer** and copy the offer summary when you need it. Keep the offer narrow: one lead source, one simple workflow, three message templates, testing, and handoff within seven days. Do not add unrelated work, software purchases, advertising, custom development, or multiple channels to this fixed-scope starter project without a separate agreement.

### Step 3: Prepare the Scope

Open **Scope builder** and replace the bracketed information. Fill in the exact client name, one lead source, and the existing tool that will hold the tracker or workflow.

| Field | Example | Why it matters |
|---|---|---|
| Client | Cedar & Stone Plumbing | Identifies the agreement and handoff materials |
| Primary lead source | Website quote form | Keeps the project limited to one workflow |
| Agreed tool | Shared Gmail inbox | Prevents an unplanned software or CRM implementation |

Copy the finished scope and send it for review. The scope should stay aligned with the $350 starter-project boundaries.

### Step 4: Send the Onboarding Questions

After the scope is accepted, open **Client onboarding**. Use this section to collect the lead source, current response process, desired response time, customer tone, approved claims, existing tools, access contact, and handoff time.

Ask for invitation-based or role-based access where possible. Do **not** ask clients to email passwords. If a client cannot provide access yet, record the delay and move the delivery date rather than guessing how their tools work.

### Step 5: Run the Kickoff Call

Open **Kickoff desk** during the 45-minute call. Work through the agenda in order: confirm scope, map the current lead journey, agree the one workflow, set the message rules, confirm the tool/access, choose testing, set dates, and recap.

The most important decisions are the following:

| Decision | Confirm it before the call ends |
|---|---|
| Lead source | Exactly one source is in this project |
| First response | Timing, sender, tone, and call to action |
| Follow-up stop rule | Booking, decline, opt-out, or the agreed final attempt |
| Tool | The existing inbox, tracker, or CRM you will use |
| Approver | One named person who can approve the messages |
| Dates | Draft, approval, test, and handoff dates |

Send a short written recap immediately after the call. If the client introduces a new lead source, new software, or a major new requirement, treat it as out-of-scope until it is separately approved.

### Step 6: Complete the Seven-Day Delivery Plan

Open **Seven-day delivery** and check off work only after it is actually complete. The usual sequence is kickoff and mapping, workflow draft, three messages, tracker configuration, tests, operating guide, and handoff.

Checking a milestone updates the delivery progress for that client only. If a client delays approval or access, leave the current milestone open and update the client on the adjusted handoff date.

### Step 7: Test the Workflow and Complete the File

Open **Messages & testing** to copy the initial response, follow-up, and final check-in templates. Replace bracketed text before giving messages to the client. Then record the agreed safe tests.

LeadFlow keeps the final completion control locked until the kickoff items, seven delivery milestones, and testing steps are logged. This makes the closeout decision visible rather than relying on memory.

### Step 8: Handoff and Follow-Up

Open **Handoff & follow-up** when the client is ready to use the workflow. Confirm the client has the workflow summary, the message templates, tracker or workflow instructions, test confirmation, and operating guide. Hold the handoff call, then use the follow-up section to propose the next sensible improvement only if it fits the client’s needs.

## 5. Export a Single Client Package

Use **Client kit** in the upper-right corner to download a plain-text package for the active client. It combines the current scope, onboarding prompts, kickoff recap, message templates, and closeout language.

Before sending it to a client, replace any bracketed placeholders and review the wording. The client package is useful for sharing working materials, but it is **not** a full backup of the whole LeadFlow collection.

## 6. Back Up All Client Workspaces

Use **Back up all** to download a plain JSON file containing every client workspace and the currently active file. Use this when you need a portable working copy or when you are moving to another browser or device.

| Backup type | Use it when | Protection |
|---|---|---|
| Plain backup | You need a convenient, editable transfer file and can protect the file yourself | The JSON is readable to anyone who has the file |
| Encrypted backup | The collection contains confidential business information or is stored outside your usual device | The file is unreadable without the passphrase |

Save plain backups only in a location you trust. If the file could be forwarded, stored in an insecure folder, or placed on a shared computer, use an encrypted backup instead.

## 7. Create an Encrypted Backup

Select **Secure backup** in the header. On a phone, this appears as the compact checkmark tool next to **Client files**.

1. Enter a passphrase of at least 12 characters.
2. Enter the exact same passphrase again.
3. Store the passphrase in a trusted password manager or another secure location **before** downloading the file.
4. Select **Create encrypted backup**.
5. Save the downloaded encrypted JSON file in the location you chose.

LeadFlow encrypts the collection locally in your browser. The passphrase is not saved in LeadFlow, is not stored in browser storage, and is not included in the backup file.

> There is no passphrase recovery. If you lose the passphrase, the encrypted backup cannot be restored.

## 8. Restore a Backup Safely

Open **Client files** and choose the import control. Select either a plain LeadFlow backup or an encrypted LeadFlow backup. LeadFlow reads and validates the file before it offers a restore choice.

### Restore a Plain Backup

After LeadFlow verifies the file, choose one of these options:

| Option | What happens | Choose it when |
|---|---|---|
| Merge | Adds the imported client files to the browser collection. Existing files stay in place. | You want to combine work from two browsers or devices. |
| Replace | Replaces the browser’s current collection with the imported collection. | The backup is the correct full collection and you want to restore it exactly. |

If you merge two collections that contain the same workspace ID, LeadFlow assigns a safe new ID to the imported copy. Review the names after the merge so you do not continue working in the wrong duplicate file.

### Restore an Encrypted Backup

When LeadFlow recognizes an encrypted file, it asks for the backup passphrase. Enter it exactly as it was used during export. The backup is decrypted locally, then checked again before LeadFlow lets you merge or replace it.

If the message says the passphrase did not unlock the file, check the passphrase carefully. The same message is also used when the encrypted data cannot be authenticated; this protects the security of the backup format. The current collection is not changed until you choose **Merge** or **Replace** after a successful unlock.

## 9. Suggested Backup Routine

For active client work, make a backup at least once a week and again before a major browser cleanup, computer change, or substantial workspace reorganization.

| Moment | Recommended action |
|---|---|
| After creating several new client files | Create a plain or encrypted collection backup |
| Before replacing browser data | Export an encrypted backup first |
| Before clearing browser data | Export an encrypted backup and verify you know the passphrase |
| After a major client handoff | Export a backup so the completed record is preserved |
| Before moving devices | Export on the old device, import on the new device, then verify several client files before removing the old copy |

## 10. Run the Automated Security Tests

The project includes automated Vitest coverage for the encrypted-backup helper. The tests verify that a valid encrypted envelope is created, the passphrase and readable client details are absent from the encrypted JSON, the correct passphrase decrypts the original content, an incorrect passphrase fails, modified ciphertext fails authentication, and malformed envelopes are rejected.

Run these commands from the project folder:

```bash
pnpm test
pnpm check
pnpm build
```

| Command | What it checks |
|---|---|
| `pnpm test` | Runs the automated encrypted-backup unit tests |
| `pnpm check` | Runs TypeScript type checking without producing output files |
| `pnpm build` | Creates a production build to confirm the application compiles |

Run all three commands after changing encryption, backup, workspace persistence, or import/restore code. A successful test command does not replace a manual check of the visible import and restore interface.

## 11. Troubleshooting

| Problem | First thing to check | Safe next action |
|---|---|---|
| A client file appears empty | Confirm you switched to the intended client file | Open **Client files**, select the correct workspace, and verify its project name |
| Work disappeared after using a different browser | Browser storage is separate per browser and device | Import a previously exported collection backup |
| A backup will not import | Confirm it is a LeadFlow JSON backup and is under the displayed size limit | Do not replace current data; try another copy of the backup |
| The encrypted backup will not unlock | Check the exact passphrase, including capitalization and spaces | Try again carefully; if unavailable, use another backup copy or the original browser data |
| The secure backup button is not labeled on phone | The control becomes an icon to preserve space | Use the checkmark tool next to **Client files** |
| The project completion gate remains locked | Check the visible counts for kickoff, delivery, and tests | Complete or deliberately revisit the missing work before closing the file |

## 12. Data and Privacy Boundaries

LeadFlow is a browser-local workspace. It is useful for a single operator working on one device or a small set of personal devices with backups. It is not a shared database, a multi-user CRM, a cloud-sync service, or a substitute for an organization’s data-retention policy.

Use encrypted backups for portability, but remember that encryption only protects the backup file when the passphrase stays private. Do not include passwords, payment information, highly sensitive customer records, or other information you are not authorized to store in the workspace.

## 13. Practical Daily and Weekly Routine

Each workday, open the active client file, read the **Today’s briefing** instruction, complete the one next action, and update the appropriate checklist immediately. This keeps the workspace accurate without creating a large end-of-week administrative task.

At the end of each week, review open delivery milestones, schedule the next client approvals or handoffs, remove any accidental duplicate client files, and export a fresh encrypted backup if the collection contains active client information.

> The best way to keep LeadFlow useful is simple: make the next action visible, complete it, record it, and protect the collection with regular backups.
